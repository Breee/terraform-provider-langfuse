# Caveats

Format: `CNN — date — (severity, owner) — symptom, versions` + what the provider does today + report.
Rule: see `../AGENTS.md` ("never hack around limitations"). Entries marked **APPROVED** carry a user-approved provider behaviour; each is shown as a note or warning box at the top of the resource page in `docs/`.

Precedent for the approved behaviours (Terraform provider practice): `google_kms_key_ring` (cannot be deleted; destroy removes it from state, documented in a note box), `github_repository` `archive_on_destroy`, `aws_acm_certificate_validation` (warning box for a resource Terraform cannot read back).

All observed on Langfuse 4.77.0 (self-hosted, `testdata/docker-compose.yml`), spec `openapi/langfuse.yml`.

- C01 — 2026-11-18 — (high, upstream) Datasets have no delete in the public API: `DELETE /api/public/v2/datasets/{name}` → 405; upstream `main` spec has list/create/get only. Provider: `langfuse_dataset` destroy removes it from state with a warning, the dataset stays; note box in the resource docs. **APPROVED 2026-11-19** (user: "follow the best practices"). Revisit when upstream adds delete: destroy would then start deleting data, so gate it behind a `deletion_policy`. Report: `upstream/langfuse-dataset-delete.md`. Issues: #25 (caveat), #30 (upstream report, not filed yet).
- C02 — 2026-11-18 — (high, upstream) Annotation queues have no update and no delete in the public API, and names are unique (400 on duplicate). Provider: every attribute is replace-only, a plan-time error demands a rename, destroy only warns; old queues are orphaned; note box in the resource docs. **APPROVED 2026-11-19** (user: "follow the best practices"). `DELETE`/`PATCH`/`PUT` on a queue → 405. Report: `upstream/langfuse-annotation-queue-lifecycle.md`. Issues: #26 (caveat), #31 (upstream report, not filed yet).
- C03 — 2026-11-18 — (medium, upstream) Annotation queue assignments have create/delete but no read or list. Provider: `langfuse_annotation_queue_assignment` Read is a no-op → no drift detection, no import; warning box in the resource docs. **APPROVED 2026-11-19** (user: "follow the best practices"): kept rather than removed, because the assignment is real configuration and the gap is stated up front. `GET .../assignments` → 405. Same report as C02. Issues: #27 (caveat), #31 (upstream report, not filed yet).
- C04 — 2026-11-18 — (medium, upstream) Score configs have no delete. Provider: destroy PATCHes `isArchived: true` (archive on destroy); note box in the resource docs. **APPROVED 2026-11-19** (user: "follow the best practices"). `DELETE` → 405. Verified 2026-11-19: an archived config does not reserve its name, a new config with the same name is accepted. Report: `upstream/langfuse-score-config-delete.md`. Issues: #28 (caveat), #32 (upstream report, not filed yet).
- C05 — 2026-11-18 — (medium, upstream) `null` does not clear fields consistently. Dataset upsert ignores `null` description/metadata; dataset item upsert ignores `null` input/expectedOutput/metadata; `PATCH /score-configs/{id}` rejects `null` description (400); `PATCH /v2/evaluation-rules/{id}` rejects `null` filter/sampling (400). Provider: sends `""` / `{}` / `[]` / `1` and maps them back to null, or forces replacement (dataset item, note box in the resource docs). **APPROVED 2026-11-19** (user: "follow the best practices"). Explicit empty strings are rejected at plan time (`LengthAtLeast(1)` on dataset and score config `description`), so state always holds the configured value. Report: `upstream/langfuse-null-clearing.md`. Issues: #29 (caveat), #33 (upstream report, not filed yet).
- C06 — 2026-11-18 — (low, upstream) Prompt labels can only be added via `PATCH /v2/prompts/{name}/versions/{v}`; removing a label needs a new version. Provider: label removal creates a new prompt version. Documented in the resource docs.
- C07 — 2026-11-18 — (low, upstream) `GET /integrations/blob-storage/{id}` returns sync status, not the configuration. Provider: Read filters the organization-wide list.
- C08 — 2026-11-18 — (low, test stack) Code evaluators are rejected locally: 412 "Code evaluations are not enabled for this deployment". `langfuse_evaluator` with `type = "code"` is unit-tested only.
- C09 — 2026-11-18 — (low, upstream) The spec declares wrong success codes for several operations (real 201 where 200 is documented and vice versa), so the generated `JSON200` fields are unreliable. Provider: `apiCall(...).decode` accepts any 2xx. Tracked in #3.
- C10 — 2026-11-18 — (low, upstream) Users created through SCIM get organization role `NONE` and cannot be assigned to annotation queues (404 "User not found or not authorized"). Use `langfuse_organization_membership`.
